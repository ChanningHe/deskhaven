# deskhaven web console

React + TypeScript + Vite single-page app. It is built to `web/dist` and will be embedded into the
deskhaven binary.

## Commands

Run from the repository root inside `nix develop` (provides node and pnpm):

```sh
pnpm -C web install --frozen-lockfile
pnpm -C web dev          # http://localhost:5173, proxies /api and /admin/api to 127.0.0.1:21114
pnpm -C web build        # -> web/dist
pnpm -C web typecheck    # tsc --noEmit (app + node configs)
pnpm -C web lint         # eslint (type-aware) + prettier --check
pnpm -C web test         # vitest + Testing Library (jsdom)
pnpm -C web i18n:check   # fails on keys missing from a locale or {{placeholders}} that differ
pnpm -C web format       # prettier --write
```

The pnpm version comes from the Nix devshell, so `package.json` has no `packageManager` field (it
would make pnpm try to download another version). `pnpm-workspace.yaml` explains its
`minimumReleaseAgeExclude` entries and when to remove them.

`src/routeTree.gen.ts` is generated by the TanStack Router plugin on `dev`/`build`. It is committed so
`typecheck` works on a fresh clone. Never edit it by hand.

There is no API client yet. Typed query hooks will be generated with orval from the admin API's
`openapi.json` into `src/api/generated` once the backend has one. The orval mutator must throw
`HttpError` (`src/lib/http-error.ts`) for non-2xx responses: the query policy depends on its `status`.

## Data fetching and errors

- **Retries** (`src/app/query-client.ts`): 4xx responses are never retried. Network errors and 5xx
  are retried once.
- **401**: any query or mutation that fails with 401 calls `onUnauthorized`, which `createApp`
  (`src/app/create-app.ts`) wires to a redirect to `/login`.
- **Route errors** use the router's `defaultErrorComponent` (translated, with retry and a link
  home); slow routes show `defaultPendingComponent`. A route only sets its own `errorComponent`
  when it needs something more specific.
- **Not found**: unknown URLs render inside the shell (`_app/$.tsx` passes them to the `_app`
  layout's `notFoundComponent`). The root `notFoundComponent` is the shell-less fallback.

## Layout

```
src/
  app/                 providers, query client, router factory
  routes/              file-based routes, kept thin: they import a page from features/
  features/<domain>/   one folder per domain (devices, users, groups, addressbooks, strategies,
                       audit, auth, client-setup, tokens, settings, overview, shell)
    components/        domain components and the page component
    api.ts             query hooks for the domain (added once the API exists)
  components/ui/       shadcn components (Base UI primitives) only, added via `pnpm dlx shadcn add`
  components/common/   shared app components (PageHeader, EmptyState, later DataTable, ...)
  i18n/                i18next setup, locales/*.json, typed resources
  lib/                 framework-free helpers (storage, theme, utils)
  test/                test setup and render helpers
public/theme-init.js   applies the saved theme before first paint (no flash, CSP-friendly)
```

## Conventions

- **Feature folders.** Code for a domain lives in `src/features/<domain>`. A route file in
  `src/routes` only binds a path to a page component.
- **ui vs common.** `components/ui` holds shadcn code only. You may adjust it, but keep it generic.
  Components that know about the app (i18n, routing, domain types) go in `components/common` or a
  feature folder.
- **i18n.** Every user-visible string goes through `t()`. Keys come from `src/i18n/locales/en.json`
  and are type-checked, so an unknown key or a key missing from `zh-CN.json` fails `tsc`. Add every
  key to all locales; `pnpm i18n:check` catches keys that exist in only one of them, and keys whose
  `{{placeholder}}` names differ between locales. Language names
  in the switcher are written in their own language and are not translated.
- **Types.** `strict` plus `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`. No `any`;
  ESLint enforces this.
- **Size.** Components stay under 200 lines. ESLint `max-lines` enforces this for `src/**/*.tsx`
  outside `components/ui`. Split a component before it gets close.
- **Styling.** Use Tailwind utilities and the semantic tokens in `src/index.css` (`bg-background`,
  `text-muted-foreground`, ...), never raw colors. The only inline styles allowed set CSS variables
  (`style={{ '--x': value }}`), and ESLint enforces this.
- **No `console.*`** in app code, enforced by ESLint.
- **Accessibility.** Use semantic landmarks, give icon-only buttons an `aria-label`, keep focus
  visible, and make sure everything works from the keyboard. Each page has exactly one `h1` (the
  `PageHeader` title, or an `EmptyState` with `headingLevel={1}` when the empty state is the page).
  After each client-side navigation, `RouteAnnouncer` moves focus to `<main>`, announces the new
  `h1` and updates `document.title`.
- **Toggles** keep a fixed `aria-label`; only `aria-expanded`/`aria-pressed` reflects the state.
- **Links that look like buttons** are `<Link className={buttonVariants(...)}>`. Base UI's
  `<Button render={<Link/>}>` would turn the link into `role="button"`.
- **Tests.** Write user-level tests with Testing Library (query by role and accessible name).
  `src/test/render-app.tsx` renders the full app at a given path.
- **Persistence.** Read and write `localStorage` only through `src/lib/storage.ts`, which falls back
  safely when storage is unavailable. Keys are namespaced `deskhaven.*`.
