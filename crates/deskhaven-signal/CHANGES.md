## Modification log (AGPL-3.0 section 5(a))

Every modification to the upstream sources is recorded below with its date, the files touched
and the task that made it. `UPSTREAM` records the base commit and per-file checksums;
`scripts/verify-upstream.sh` checks the vendored commit against upstream.

- 2026-11-02, M1-01: vendored verbatim at 873230e35a8805de7fd057e7eb763c46f7a174ef (upstream commit
  dated 2026-10-10), in repository commit f25f49240b5e76eeff0cc83d51ac4af324b7ee1f.
  Files (under `upstream-src/`, not yet compiled): `rendezvous_server.rs`, `peer.rs`, `common.rs`,
  `lib.rs`, `LICENSE`. No modifications. (Since M1-02 the files live in `src/` and `LICENSE` at
  the crate root; see below.)
- 2026-11-02, M1-02: moved `upstream-src/{rendezvous_server,peer,common,lib}.rs` to `src/` and
  `upstream-src/LICENSE` to `LICENSE` (crate root) with `git mv`, contents unchanged, in a commit
  of its own. Upstream `lib.rs` replaced the previous one-line placeholder `src/lib.rs`.
  The `.gitattributes` / `.editorconfig` verbatim-protection rules were removed because the code
  is now maintained here. `scripts/verify-upstream.sh` still checks the vendoring commit
  (unchanged).
- 2026-11-02, M1-02: builds against hbb_common `fae47e024dd83cef6aaecde0aa7d11731df11649`
  (Cargo git dependency, the rev RustDesk client master pins) instead of the upstream submodule
  at `69cea8d`. The crate stays on edition 2021 like upstream (edition 2024 changes the drop
  scope of `if let` / tail-expression temporaries, which hold lock guards here, and makes
  `std::env::set_var` unsafe while the workspace denies `unsafe_code`; `set_arg` uses it until
  M1-03).
- 2026-11-02, M1-02: `database.rs` (sqlx 0.6 + deadpool) was never vendored; new `src/database.rs`
  is an in-memory stand-in with the same `Database::{get_peer, insert_peer, update_pk}`
  signatures (constructed with `Database::default()`) and a reduced `Peer` (`guid`, `uuid`,
  `pk`, `info`). Nothing persists across restarts, so UUID_MISMATCH (anti id-hijack) only
  protects ids registered since the last start; the stub must not be wired into
  `deskhaven serve` and is replaced by the persistent `PeerStore` trait in M1-05.
- 2026-11-02, M1-02: `peer.rs` `PeerMap::new`: removed the `DB_URL` resolution (Windows icon
  path / `./db_v2.sqlite3` default) and its `DB_URL=...` log line, which no longer described
  anything; it now builds `database::Database::default()`.
- 2026-11-02, M1-02: `version.rs` (generated by upstream `build.rs`) was never vendored and its
  only users were removed (next entry), so `lib.rs` drops `mod version;` instead of stubbing it.
- 2026-11-02, M1-02: `common.rs`: removed `init_args` (clap 2 + rust-ini; only called by the
  upstream binaries, which are not vendored) and `check_software_update` /
  `check_software_update_` (daily version report to rustdesk.com via reqwest; only called by
  upstream `main.rs`). `set_arg` is kept because the upstream tests use it.
- 2026-11-02, M1-02, hbb_common API drift: `rendezvous_server.rs` `get_pk`:
  `hbb_common::message_proto::IdPk` -> `hbb_common::rendezvous_proto::IdPk` (hbb_common removed
  `message.proto`; `IdPk` moved to `rendezvous.proto` with the same fields).
- 2026-11-02, M1-02, tungstenite 0.17 -> 0.29 API drift: `rendezvous_server.rs` `send_to_sink`:
  `Message::Binary(bytes)` -> `Message::Binary(bytes.into())` (the payload is now `Bytes`).
- 2026-11-02, M1-02, warning fixes, no behavior change: in `rendezvous_server.rs`, unused bindings
  renamed (`key` -> `_key` in `handle_udp`, `ph`/`phs`/`la` -> `_ph`/`_phs`/`_la`) and needless
  `mut` dropped on `start` in `check_cmd`; `#[allow(dead_code)]` on unused upstream items
  (`handle_udp_punch_hole_request`, `peer.rs` `UserStatusMap` and `is_in_memory`);
  `#[allow(deprecated)]` on `tempfile::TempPath::from_path` in `common.rs` (its replacement
  `try_from_path` absolutizes relative paths); `common.rs` tests import `hbb_common::tokio`
  explicitly (it previously came in through `use super::*`) and carry `#[allow(unsafe_code)]`
  (libc `umask` / `setrlimit` calls in the upstream key-file tests).
- 2026-11-02, M1-02: `lib.rs` gained a crate doc comment and per-module `#[allow(...)]` on the
  vendored module declarations, only for the clippy lints each one trips: `rendezvous_server`
  (`unwrap_used`, `unused_io_amount`, `unnecessary_unwrap`, `unnecessary_get_then_check`,
  `too_many_arguments`, `result_large_err`, `needless_lifetimes`, `manual_div_ceil`,
  `collapsible_match`, `useless_borrows_in_formatting`) and `peer` (`unwrap_used`); `common`
  trips none. Non-vendored modules get the full workspace lints. Remove them incrementally.
- 2026-11-02, M1-02: each modified vendored file (`lib.rs`, `rendezvous_server.rs`, `peer.rs`,
  `common.rs`) starts with the notice
  `// Modified by deskhaven; see crates/deskhaven-signal/CHANGES.md (AGPL-3.0 §5a).`
- 2026-11-02, M1-02: whole crate formatted with rustfmt in a separate style-only commit.
- 2026-11-02, M1-02, dependencies (vs. upstream `Cargo.toml`): kept, at hbb_common-compatible
  versions: `serde`, `serde_derive`, `serde_json`, `lazy_static`, `once_cell`, `sodiumoxide`,
  `tempfile` (used by non-test key-file code, so a normal dependency), `uuid`, `chrono`,
  `ipnetwork` 0.20, `local-ip-address` 0.5, and `base64` 0.13 (kept so key decoding stays
  identical: 0.13 tolerates missing padding, 0.22 does not). `tungstenite` / `tokio-tungstenite`
  0.17 -> 0.29 (tokio-tungstenite from the same rustdesk-org fork and rev as hbb_common; fixes
  RUSTSEC-2023-0065). Dropped: `sqlx`, `deadpool`, `async-trait`, `axum`, `tower-http`, `http`,
  `headers`, `jsonwebtoken`, `bcrypt`, `minreq`, `machine-uid`, `mac_address`, `whoami`, `flate2`,
  `regex`, `clap`, `rust-ini`, `flexi_logger`, `reqwest`, `async-speed-limit`, `dns-lookup`,
  `ping` (unused by the vendored hbbs files, or used only by removed code).
